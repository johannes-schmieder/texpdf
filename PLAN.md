# texpdf plan

Development branch: **main**

Stable release: **immutable `v0.1.0`**

Version 0.1.0 is published on GitHub and has been submitted to SSC. `main` is
development toward the next patch or feature release.

Required runtimes: **macOS ARM64, Linux x86-64, and Windows x86-64**

The macOS package remains universal: its Intel slice is built and inspected as
a compatibility binary, but Intel/Rosetta runtime testing and qualification are
not part of the project.

The machine-readable scope is `release/scope.json`. Linux enforces a GLIBC 2.28
ceiling and licensed Stata/MP 18 and 19 evidence from BU SCC. Windows requires
licensed Stata/MP 19. The 0.1.0 qualification is complete; future releases
repeat the applicable exact-source gates.

## Evidence rules

Project state is determined by immutable exact-SHA receipts, target records,
artifact manifests, license status, and memory-attempt records. `STATUS.md` and
`release/READINESS.*` are generated by `tools/sync_project_state.py`; branch
position and build-only artifacts are never treated as runtime qualification.

- Three runnable help examples and a synthetic real-world compatibility corpus.
- macOS universal, Linux x86-64, and Windows x86-64 packages.
- Apple Silicon, Linux, and Windows qualification under the recorded evidence
  policy, including the 1,000-call durability gates.

- Public repository hardening, immutable tags, and verified release assets.

Detailed implementation and qualification history remains available in the
`v0.1.0` tag, `CHANGELOG.md`, and the machine-readable release records.

Never replace the final tag or assets. Any source change requested after
`v0.1.0` becomes `0.1.1`.

## Release discipline

For each future release, test a committed source, require the applicable
exact-SHA target and license evidence, and regenerate canonical state. Never
replace a final tag or asset, force-push release history, or describe missing
evidence as a pass.
